# 001-app-shell 功能规格 — 应用外壳与基础设施

> 文档类型：As-Built 描述性规格（如实记录当前代码已实现的行为，非目标设计）
> 模块编号：001-app-shell（应用外壳与基础设施）
> 项目：tpl-app-web（tpl-workspace网页端）
> 生成日期：2026-08-12
> 规格语言约定：本模块为基础设施模块，其"用户"为开发者、集成方与依赖本模块的业务模块，而非终端用户用户。

## 1. 模块概述 (Module Overview)

应用外壳与基础设施模块为整个前端应用提供可运行的地基，覆盖以下职责：

- **应用引导**：定义应用从启动到可交互的装配顺序与挂载方式。
- **页面外壳**：为登录后的页面提供统一骨架（固定顶部导航条 + 内容插槽），承载品牌标识"tpl-workspace"与退出操作。
- **导航系统**：定义全部页面地址、访问要求（访客页 / 需登录页）与访问控制规则，并提供登录成功后回跳能力。
- **HTTP 通信基础设施**：提供统一的请求出口，自动附加会话凭据、统一解包响应结构、统一处理业务错误与认证失效。
- **全局视觉体系**：以设计令牌为核心的全局样式层与通用组件类，保证所有页面视觉一致、开发效率高。
- **工程与部署环境**：定义构建基础路径、本地开发代理、类型质量门禁与 HTML 宿主。

本模块是其他业务模块（用户认证、个人中心）的公共底座：业务模块依赖其外壳、请求客户端与设计令牌；本模块本身不承载任何具体业务功能。

## 2. 用户故事 (User Stories)

US-001-01 作为开发者，我希望应用启动时自动完成核心依赖装配并挂载到宿主节点，以便我无需关心初始化细节即可直接开发页面。

US-001-02 作为开发者，我希望所有登录后的页面共享一个统一外壳（品牌顶栏 + 内容区 + 退出），以便页面外观一致且退出能力开箱即用。

US-001-03 作为开发者，我希望导航系统自动执行访问控制（访客页 / 需登录页），以便业务页面无需重复实现鉴权逻辑。

US-001-04 作为开发者，我希望通过统一的请求出口发起接口调用，自动携带会话凭据、统一解包响应并处理错误，以便业务代码只关心业务数据。

US-001-05 作为开发者，我希望全局样式层提供设计令牌与通用组件类，以便任何页面都能快速获得一致且合格的视觉。

US-001-06 作为开发者，我希望本地开发时接口请求自动代理到本地后端服务，以便前后端并行开发与联调。

US-001-07 作为部署方，我希望应用部署于统一子路径下、静态资源与页面地址均带该前缀，以便与部署网关及其他应用共存。

## 3. 功能需求 (Functional Requirements)

### 3.1 应用引导与根组件

**FR-001-001 应用引导**
- 应用 MUST 提供单一启动入口。
- 启动过程 MUST 按固定顺序装配：全局状态容器、导航系统，最后挂载到 HTML 宿主提供的根节点。
- 全局样式 MUST 在挂载之前加载完成。

**FR-001-002 根组件**
- 根组件 MUST 仅充当导航出口，渲染当前导航规则匹配到的页面。
- 根组件 MUST NOT 承载任何业务逻辑或页面内容。

### 3.2 应用外壳

**FR-001-003 应用外壳布局**
- 登录后的页面 MUST 由统一外壳承载。
- 外壳 MUST 包含顶部导航条与内容插槽两部分。
- 顶部导航条 MUST 在页面滚动时保持固定在视口顶部（sticky），且置于较高层级以免被内容覆盖。
- 导航条 MUST 展示品牌标识"tpl-workspace"。
- 内容区 MUST 通过插槽机制接收页面内容。
- 导航条内部内容与内容区 MUST 限制最大宽度（960px）并水平居中。
- 外壳 MUST 占满视口高度（min-height 100vh），内容区 MUST 占据剩余垂直空间。
- 窄屏（宽度 ≤ 640px）下，内容区内边距 MUST 缩减。

**FR-001-004 退出登录**
- 外壳 MUST 提供退出操作，位于顶部导航条一侧。
- 退出操作 MUST 携带图标与无障碍标签（按钮语义）。
- 触发退出时 MUST 依次执行：请求注销会话、清理本地会话状态、导航至登录页。
- 注销请求无论成功与否，本地会话状态 MUST 均被清理（保证本地一致）。
- 退出后 MUST 导航到登录页。

### 3.3 导航系统与访问控制

**FR-001-005 导航规则**
- 导航系统 MUST 使用浏览器历史模式，并基于统一基础路径运行。
- 系统 MUST 定义以下导航规则：
  - 根路径 MUST 重定向到个人中心；
  - 登录页 MUST 声明为访客可访问；
  - 注册页 MUST 声明为访客可访问；
  - 个人中心 MUST 声明为需登录。
- 页面组件 MUST 按需加载（懒加载），不得随应用启动全部加载。
- 根路径重定向的跳转目标 MUST 由受保护访问规则管辖。

**FR-001-006 访问控制守卫**
- 每次导航切换前 MUST 执行访问控制检查。
- 未登录访问需登录页面时 MUST 重定向到登录页，并携带原目标地址作为回跳参数（登录成功后返回原地址）。
- 已登录访问访客页面时 MUST 重定向到个人中心。
- 其余导航 MUST 正常放行。

### 3.4 全局视觉体系

**FR-001-007 设计令牌**
- 全局样式层 MUST 在根作用域以设计令牌形式声明以下类别：
  - 颜色令牌 MUST 覆盖 10 个语义：主色、强调色、成功色、错误色、页面背景、卡片背景、正文文字、次级文字、边框、禁用/骨架背景；
  - 字体令牌 MUST 提供 3 套字体栈：正文、等宽、数字；
  - 间距令牌 MUST 基于 4px 基准，覆盖至少 8 级；
  - 圆角令牌 MUST 覆盖 4 级：小、中、大、胶囊；
  - 阴影令牌 MUST 覆盖 2 级：卡片常态、卡片悬停；
  - 字号令牌 MUST 覆盖至少 7 级：展示级至说明级；
  - 缓动令牌 MUST 覆盖 2 种：快速输出、标准过渡。
- 组件与页面样式 SHOULD 优先从令牌取值，而非硬编码数值。
- 令牌语义 MUST 与业务色彩含义映射一致（如成功态对应成功色、错误态对应错误色）。

**FR-001-008 全局重置与基础样式**
- 全局样式 MUST 提供 reset：统一盒模型、清除默认外边距/内边距。
- 正文 MUST 应用页面背景色、正文文字色与正文字体。
- 链接 MUST 去除下划线并继承文字色；图片 MUST 响应式最大宽度；按钮/表单控件 MUST 继承字体并统一光标语义。

**FR-001-009 通用组件类**
- 全局样式层 MUST 提供以下通用类：
  - 页面容器类：最大宽度 960px、水平居中、统一内边距；
  - 卡片类：白底、圆角、卡片阴影、内边距；
  - 表单输入类：统一尺寸、边框、聚焦态（边框变色 + 焦点环）、错误态（边框变错误色 + 错误焦点环），并 MUST 支持下拉控件隐藏默认外观、显示自定义箭头；
  - 按钮系列：基础按钮类 MUST 支持主色、强调色、幽灵三种视觉变体、禁用态（半透明 + 禁用手型），MAY 支持大尺寸与全宽修饰，点击 MAY 有轻微缩放反馈；
  - 骨架屏类：基础块与行级骨架各一种，用于加载态占位；
  - 轻提示类：固定悬浮于视口顶部居中、上滑动画入场，MUST 支持成功与错误两种语义变体。

**FR-001-010 动画与动效偏好**
- 全局 MUST 定义淡入、上滑、旋转三种关键帧动画。
- 轻提示 MUST 以上滑动画入场。
- 系统 MUST 尊重系统级"减少动画"偏好：开启时 MUST 最小化动画与过渡时长、禁止循环动画。

**FR-001-011 可访问性**
- 全局 MUST 提供清晰的键盘焦点可见样式（focus-visible），聚焦轮廓 MUST 使用主色且带偏移。

### 3.5 HTTP 通信基础设施

**FR-001-012 请求客户端**
- 系统 MUST 提供单一 HTTP 客户端实例供全局复用（单例）。
- 客户端 MUST 使用同源相对地址作为基础地址（不写死跨域主机），并 MUST 配置统一超时（15 秒）。
- 每次请求发出前 MUST 自动检查本地会话凭据，若存在 MUST 附加到请求认证头。

**FR-001-013 统一响应契约**
- 系统 MUST 定义统一响应包装结构：业务码、消息、数据载荷。
- 业务成功时，客户端 MUST 向调用方返回解包后的数据载荷。
- 业务失败时，客户端 MUST 以标准错误对象拒绝调用方，错误消息优先级为：服务端消息 > 通用兜底文案。

**FR-001-014 认证失效与错误处理**
- 当响应携带认证失效信号（业务码为 401 或 HTTP 状态为 401）时，客户端 MUST：
  - 清理本地会话凭据；
  - 整页跳转到登录页。
- 网络错误或其他 HTTP 错误时，客户端 MUST 提供兜底错误消息，优先级为：服务端消息 > 网络层消息 > 固定兜底文案。
- 客户端 MUST NOT 吞掉错误：所有失败路径 MUST 以标准错误对象向上抛出。

### 3.6 工程与部署环境

**FR-001-015 基础路径与资源**
- 应用构建产物 MUST 统一挂载于固定子路径下（基础路径）。
- 导航系统的基础路径 MUST 与构建基础路径一致。
- 源码引用 MUST 使用统一别名指向源码根目录，禁止依赖深层相对路径。

**FR-001-016 开发代理**
- 本地开发服务器 MUST 支持将业务接口前缀与认证接口前缀代理至本地后端服务。
- 开发服务器 MUST 可监听所有网络接口（host 0.0.0.0）以便跨设备联调。

**FR-001-017 HTML 宿主**
- HTML 宿主 MUST 声明中文语言区域（lang=zh-CN）。
- 页面标题 MUST 为品牌名"tpl-workspace"。
- HTML 宿主 MUST 提供：应用挂载节点、入口脚本引用、移动端视口配置（含安全区域）。
- 品牌图标 MUST 内联于宿主中，MAY 不依赖外部文件。

**FR-001-018 质量门禁**
- 类型检查 MUST 开启严格模式。
- 未使用的局部声明与参数 MUST 触发构建失败。
- 构建流程 MUST 在执行产物生成前完成完整类型检查。
- 依赖 MUST 通过统一包管理器安装并锁定版本，MAY 限制仅允许必要的原生构建依赖执行安装脚本（保证可复现构建）。

## 4. 关键实体 (Key Entities)

| 实体 | 说明 | 关键属性 |
|---|---|---|
| 应用外壳 (App Shell) | 登录后页面统一骨架 | 品牌标识、固定顶部导航条、内容插槽、退出操作、最大宽度 |
| 导航规则 (Navigation Rule) | 页面地址到组件与访问要求的映射 | 路径、名称、组件（按需加载）、访问要求（访客 / 需登录） |
| 回跳参数 (Redirect Parameter) | 访问控制重定向时携带的原目标地址 | 随登录页查询参数传递，登录成功后回跳 |
| 会话凭据 (Session Credential) | 本地持久化的认证凭据 | 本地存储键、请求认证头位置 |
| 响应包装 (Response Envelope) | 后端统一响应结构 | 业务码、消息、数据载荷 |
| 设计令牌 (Design Token) | 全局视觉原子值 | 颜色×10、字体栈×3、间距×8、圆角×4、阴影×2、字号×7、缓动×2 |
| 通用组件类 (Shared Component Class) | 全局复用样式组件 | 页面容器、卡片、表单输入、按钮、骨架屏、轻提示 |
| 工程配置 (Build Configuration) | 构建与开发环境参数 | 基础路径、源码别名、开发代理、类型门禁 |

## 5. 验收场景 (Acceptance Scenarios)

AC-001-01 应用启动：打开应用地址，应用正常渲染；访问根路径时自动进入个人中心地址（未登录则先进入登录流程）。

AC-001-02 受保护访问：未登录直接访问个人中心地址 → 被重定向到登录页，且登录页地址携带原目标地址回跳参数；登录成功后返回原目标地址。

AC-001-03 访客页拦截：已登录状态下访问登录页或注册页 → 被重定向到个人中心。

AC-001-04 外壳渲染：登录后页面显示统一外壳：顶部固定导航条含品牌"tpl-workspace"与退出按钮；内容区最大宽度 960px 并水平居中。

AC-001-05 退出登录：点击退出按钮 → 会话凭据被清理 → 跳转到登录页。

AC-001-06 会话失效：任意请求返回认证失效信号（业务码 401 或 HTTP 401）→ 本地凭据被清除，浏览器整页跳转登录页。

AC-001-07 成功解包与失败传播：业务成功时调用方收到解包后的数据载荷；业务失败时收到携带服务端消息的标准错误对象。

AC-001-08 响应式：视口宽度降至 640px 以下时，内容区内边距缩减，布局不溢出。

AC-001-09 构建产物：执行构建命令成功产出静态产物，全部资源带基础路径前缀；构建前完成类型检查（存在未使用声明时构建失败）。

AC-001-10 开发代理：开发环境下业务与认证接口前缀请求被代理至本地后端服务。

## 6. 非功能需求 (Non-Functional Requirements)

NFR-001-01 性能：业务页面组件 MUST 按需加载（懒加载），首屏仅加载必要代码，避免整包加载。
NFR-001-02 可访问性：键盘焦点可见样式 MUST 全局生效；退出操作 MUST 具有无障碍标签；系统 MUST 尊重系统级减少动画偏好。
NFR-001-03 一致性：视觉属性 MUST 源自设计令牌；组件级样式 MUST 作用域隔离，不得污染全局（全局样式层除外）。
NFR-001-04 可维护性：类型检查 MUST 严格；未使用代码 MUST 触发构建失败；错误处理 MUST 有统一出口，不得在基础设施层吞错。
NFR-001-05 兼容性：页面 MUST 适配移动端视口（含安全区域）；宿主 MUST 声明中文语言区域与移动端 viewport。
NFR-001-06 安全性：会话凭据 MUST 仅存于本地存储并经认证头传输；认证失效 MUST 自动清理凭据并跳转登录页；登出 MUST 无论后端结果如何均清理本地会话。
NFR-001-07 可部署性：应用 MUST 支持子路径部署，静态资源地址与路由基础地址 MUST 与该子路径一致。

## 7. 依赖关系 (Dependencies)

- **上游依赖（本模块消费）**：
  - 后端服务：注销会话接口；会话凭据的签发与校验（经认证头）。
  - 业务模块 001-user-auth 提供的会话状态容器（凭据持有、登录态派生、登出动作）——外壳退出操作与导航守卫均消费之。
  - 业务模块 002-profile 的个人中心页面——作为需登录导航目标与根路径重定向目标。
- **下游被依赖（本模块提供）**：
  - 业务页面依赖外壳布局（通过内容插槽承载页面内容）。
  - 业务模块的接口调用依赖统一请求客户端（凭据注入、响应解包、错误与 401 处理）。
  - 所有模块的样式依赖设计令牌与通用组件类。
- **外部集成**：
  - 部署网关需将本应用挂载于基础路径，并将业务/认证接口前缀反向代理至后端服务。

## 8. 待澄清事项 (Needs Clarification)

[NEEDS CLARIFICATION #1] 认证失效后的整页跳转目标当前未携带基础路径前缀（直接跳转登录页地址本身），与导航系统基础路径不一致。需澄清：该跳转是否由部署网关统一补全前缀，还是应由本模块内补齐？

[NEEDS CLARIFICATION #2] 请求认证头中附加的凭据为原始值，未附加标准类型前缀。需澄清：后端会话体系是否接受该格式（现有实现与后端联调是否已验证通过）？

[NEEDS CLARIFICATION #3] 应用外壳当前仅被个人中心页面使用；未来新增需登录页面时，是否统一复用同一外壳（本模块未定义"需登录页面自动套外壳"的强制机制）？
