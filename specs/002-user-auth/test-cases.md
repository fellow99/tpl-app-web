# 002-user-auth 测试用例

> 模块：002-user-auth（用户认证）
> 对应规格：[spec.md](./spec.md)
> 生成日期：2026-08-12

## 测试范围

本测试用例覆盖用户认证模块的三个核心页面：登录页、注册页，以及认证相关的会话管理功能。

---

## 一、登录页测试用例

### TC-AUTH-LOGIN-001：正常登录流程

- **前置条件**：验证码服务开启，用户已有注册账号
- **操作步骤**：
  1. 打开登录页（`/login`）
  2. 输入正确的用户名
  3. 输入正确的密码
  4. 输入验证码图片中的 4 位字符
  5. 点击"登录"按钮
- **预期结果**：
  - 按钮变为"登录中..."且被禁用
  - 登录成功后跳转至个人中心页（`/profile`）
  - 页面顶部导航栏显示"tpl-workspace"品牌标识和"退出"按钮

### TC-AUTH-LOGIN-002：登录后回跳原页面

- **前置条件**：用户未登录
- **操作步骤**：
  1. 直接在浏览器地址栏访问 `/profile`
  2. 确认被重定向到 `/login?redirect=/profile`
  3. 完成登录
- **预期结果**：登录成功后自动跳回 `/profile`

### TC-AUTH-LOGIN-003：用户名为空

- **前置条件**：验证码已加载
- **操作步骤**：
  1. 打开登录页
  2. 不填写用户名
  3. 填写密码和验证码
  4. 点击"登录"
- **预期结果**：
  - 显示红色错误提示"请填写完整信息"
  - 不发起网络请求

### TC-AUTH-LOGIN-004：密码为空

- **前置条件**：验证码已加载
- **操作步骤**：
  1. 填写用户名
  2. 不填写密码
  3. 填写验证码
  4. 点击"登录"
- **预期结果**：显示错误提示"请填写完整信息"

### TC-AUTH-LOGIN-005：验证码为空（验证码开启时）

- **前置条件**：验证码服务开启
- **操作步骤**：
  1. 填写用户名和密码
  2. 不填写验证码
  3. 点击"登录"
- **预期结果**：显示错误提示"请输入验证码"

### TC-AUTH-LOGIN-006：验证码错误

- **前置条件**：用户名和密码正确
- **操作步骤**：
  1. 填写正确的用户名和密码
  2. 输入错误的验证码
  3. 点击"登录"
- **预期结果**：
  - 显示服务端返回的错误信息
  - 验证码图片自动刷新
  - 验证码输入框清空

### TC-AUTH-LOGIN-007：用户名或密码错误

- **前置条件**：验证码正确
- **操作步骤**：
  1. 输入不存在的用户名或错误的密码
  2. 输入正确的验证码
  3. 点击"登录"
- **预期结果**：
  - 显示服务端返回的错误信息（如"用户名或密码错误"）
  - 验证码图片自动刷新

### TC-AUTH-LOGIN-008：验证码刷新

- **操作步骤**：
  1. 打开登录页，观察初始验证码图片
  2. 点击验证码图片
- **预期结果**：
  - 验证码图片更新为新图片
  - 验证码输入框清空
  - 错误提示清除（如有）

### TC-AUTH-LOGIN-009：验证码服务关闭

- **前置条件**：后端关闭验证码服务（`captchaEnabled: false`）
- **操作步骤**：打开登录页
- **预期结果**：验证码输入框和图片不显示，登录表单只包含用户名和密码

### TC-AUTH-LOGIN-010：已登录用户访问登录页

- **前置条件**：用户已登录
- **操作步骤**：在浏览器访问 `/login`
- **预期结果**：自动重定向到 `/profile`

### TC-AUTH-LOGIN-011：网络异常

- **前置条件**：后端服务不可达
- **操作步骤**：
  1. 填写完整的登录信息
  2. 点击"登录"
- **预期结果**：
  - 显示错误提示（如"网络错误"）
  - 验证码自动刷新

### TC-AUTH-LOGIN-012：重复提交防护

- **前置条件**：网络响应较慢
- **操作步骤**：
  1. 填写完整登录信息
  2. 连续快速点击"登录"按钮两次
- **预期结果**：
  - 首次点击后按钮变为"登录中..."并被禁用
  - 第二次点击不触发额外请求

## 二、注册页测试用例

### TC-AUTH-REG-001：正常注册流程

- **操作步骤**：
  1. 打开注册页（`/register`）
  2. 输入新用户名
  3. 输入密码
  4. 确认密码，输入相同密码
  5. 输入验证码
  6. 点击"注册"按钮
- **预期结果**：
  - 按钮变为"注册中..."且被禁用
  - 注册成功后显示绿色 toast 提示"注册成功，请登录"
  - 约 2 秒后自动跳转到登录页 `/login`

### TC-AUTH-REG-002：两次密码不一致

- **操作步骤**：
  1. 输入密码为 `abc123`
  2. 确认密码输入 `abc456`
- **预期结果**：
  - 确认密码输入框高亮红色边框
  - 输入框下方显示红色文字"两次输入的密码不一致"
  - 注册按钮点击后被拦截

### TC-AUTH-REG-003：密码一致后错误消失

- **前置条件**：确认密码输入框已有内容且与密码不一致
- **操作步骤**：将确认密码修改为与密码一致
- **预期结果**：红色高亮和错误提示消失

### TC-AUTH-REG-004：用户名为空

- **操作步骤**：
  1. 不填写用户名
  2. 填写其他所有必填项
  3. 点击"注册"
- **预期结果**：显示错误提示"请填写完整信息"

### TC-AUTH-REG-005：密码为空

- **操作步骤**：
  1. 填写用户名、确认密码、验证码
  2. 不填写密码
  3. 点击"注册"
- **预期结果**：显示错误提示"请填写完整信息"

### TC-AUTH-REG-006：注册后不自动登录

- **前置条件**：注册成功
- **操作步骤**：注册成功后，在自动跳转前尝试访问 `/profile`
- **预期结果**：被重定向到登录页（说明注册不会自动建立会话）

### TC-AUTH-REG-007：已注册用户再次注册

- **前置条件**：用户名已存在
- **操作步骤**：使用已存在的用户名完成注册表单并提交
- **预期结果**：
  - 显示服务端返回的错误信息
  - 验证码自动刷新

### TC-AUTH-REG-008：已登录用户访问注册页

- **前置条件**：用户已登录
- **操作步骤**：在浏览器访问 `/register`
- **预期结果**：自动重定向到 `/profile`

## 三、会话管理测试用例

### TC-AUTH-SESSION-001：正常登出

- **前置条件**：用户已登录，在个人中心页面
- **操作步骤**：点击页面右上角"退出"按钮
- **预期结果**：
  - 跳转到登录页 `/login`
  - 再次访问 `/profile` 被重定向到登录页（token 已清除）

### TC-AUTH-SESSION-002：Token 持久化（刷新保持登录）

- **前置条件**：用户已登录
- **操作步骤**：刷新浏览器页面（F5）
- **预期结果**：保持在当前页面，不会跳转到登录页

### TC-AUTH-SESSION-003：Token 过期自动登出

- **前置条件**：用户已登录，后端 token 已过期
- **操作步骤**：在个人中心页面点击"重试"或刷新页面
- **预期结果**：
  - API 返回 401
  - 自动清除本地 token
  - 页面跳转到登录页

### TC-AUTH-SESSION-004：无 Token 访问受保护页面

- **前置条件**：本地无 token（清除浏览器 localStorage）
- **操作步骤**：访问 `/profile`
- **预期结果**：被重定向到 `/login?redirect=/profile`

### TC-AUTH-SESSION-005：登出后浏览器后退

- **前置条件**：已登出
- **操作步骤**：点击浏览器后退按钮
- **预期结果**：由于路由守卫检测到未登录，重定向到登录页

## 四、响应式测试用例

### TC-AUTH-RESP-001：手机端登录页布局

- **操作步骤**：将浏览器窗口缩小到 375px 宽度（iPhone 尺寸），打开登录页
- **预期结果**：
  - 登录卡片占满可用宽度
  - 表单元素不溢出
  - 验证码图片与输入框在同一行，排列合理
  - 卡片垂直居中显示

### TC-AUTH-RESP-002：手机端注册页布局

- **操作步骤**：将浏览器窗口缩小到 375px 宽度，打开注册页
- **预期结果**：
  - 注册卡片占满可用宽度
  - 所有表单元素不溢出
  - 成功 toast 居中显示

## 五、可访问性测试用例

### TC-AUTH-A11Y-001：键盘导航登录

- **操作步骤**：
  1. 打开登录页
  2. 使用 Tab 键依次在用户名、密码、验证码输入框和登录按钮之间切换
- **预期结果**：
  - 每个聚焦元素显示清晰的焦点轮廓
  - 焦点顺序符合视觉布局顺序
  - 验证码图片可通过 Tab 聚焦（如适用）

### TC-AUTH-A11Y-002：验证码图片替代文本

- **操作步骤**：检查验证码图片的 HTML 属性
- **预期结果**：`alt` 属性值为"验证码"，`title` 属性值为"点击刷新验证码"

### TC-AUTH-A11Y-003：减少动态效果

- **前置条件**：操作系统设置中开启"减少动态效果"
- **操作步骤**：打开登录页，进行登录操作
- **预期结果**：动画和过渡效果被禁用或缩短
