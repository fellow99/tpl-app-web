## 3. 关键数据结构（Key Data Structures）

```ts
// src/lang/index.ts
export const SUPPORTED_LOCALES = ['zh-CN', 'en-US', 'zh-TW'] as const
export type Locale = (typeof SUPPORTED_LOCALES)[number]
const STORAGE_KEY = 'language'
export const DEFAULT_LOCALE: Locale = 'zh-CN'

// src/api/index.ts
export interface ApiResponse<T = unknown> {
  code: number
  msg: string          // i18n key
  msgArgs?: unknown[]  // 可选插值参数
  data: T
}

// src/lang/zh-CN.ts（sync 生成，三语言 key 一致）
const messages = { "app.name": "tpl-workspace", "message.success": "操作成功", /* ... */ } // 214 key
export default messages
```

## 4. 接口契约（Interface Contracts）

### 4.1 翻译工具契约

```ts
// src/utils/i18n.ts
export function translateApiMessage(msg: string, args?: Record<string, unknown> | unknown[]): string
```

| 输入 | 输出 |
|---|---|
| `msg` 命中语料 | 对应语言文案 |
| `msg` 带插值（`args` 非空数组） | `i18n.global.t(msg, args)` 插值后文案 |
| `msg` 未命中（语料无该 key） | 原 `msg`（vue-i18n 返回 key 本身） |
| `msg` 命中但翻译为空串 | 回退原 `msg`（`translated || msg`） |
| `msg` 为空 | 原样返回空串 |

### 4.2 拦截器契约（src/api/index.ts）

后端：tpl-app-api 统一响应 `R<T>`，`code === 200` 成功，`code !== 200` 失败且 `msg` 为 i18n key。

- 业务失败（`data.code !== 200`）：`Promise.reject(new Error(translateApiMessage(data.msg, data.msgArgs)))`；其中 `code === 401` 额外清理 token 并跳 `/web/login`。
- HTTP 异常（无响应体）：`error.response?.data?.msg` 存在则翻译，否则用 `error.message`，最终兜底 `translateApiMessage('message.error.network')`。
- 调用方（view/store）以 `e instanceof Error ? e.message : ...` 捕获展示，无需感知 key 与翻译。

## 5. 实现策略（Implementation Strategy）

### 5.1 语料接入（src/lang/）

- `zh-CN.ts` / `en-US.ts` / `zh-TW.ts` 由父工程 `i18n/scripts/sync-i18n.mjs` 生成，文件头 `// Auto-generated by i18n/scripts/sync-i18n.mjs — 请勿手动编辑`，各 214 key，`export default messages`。
- `index.ts`（手写）：
  - `normalizeSystemLocale(lang)` 归一化系统语言：`zh` 含 `tw/hk/mo/hant` → `zh-TW`；`zh` → `zh-CN`；`en` → `en-US`；其余 → `zh-CN`。
  - `getLanguage()`：localStorage `language` 命中白名单则用，否则 `normalizeSystemLocale(navigator.language)`。
  - `createI18n({ legacy: false, globalInjection: true, locale: getLanguage(), fallbackLocale: 'zh-CN', messages })`。
  - `setLanguage(lang)`：写 localStorage + `i18n.global.locale.value = lang`。

### 5.2 翻译工具（src/utils/i18n.ts）

- `translateApiMessage(msg, args?)`：空 msg 直接返回；`args` 非空数组时 `i18n.global.t(msg, args)` 插值，否则 `i18n.global.t(msg)`；`translated || msg` 兜底空串/未命中。

### 5.3 拦截器翻译（src/api/index.ts）

- 扩展 `ApiResponse<T>` 增加 `msgArgs?: unknown[]`。
- 响应拦截器成功分支：`code !== 200` 时 `Promise.reject(new Error(translateApiMessage(data.msg, data.msgArgs)))`（401 先清理 token 跳登录）。
- 错误分支：优先翻译 `error.response.data.msg`，无则 `error.message`，最终兜底 `message.error.network`。

### 5.4 视图文案迁移（src/views/*.vue + AppLayout.vue）

- 模板文案统一 `$t('key')`，脚本内动态文案用 `const { t } = useI18n()` 后 `t('key')`。
- 顶栏语言切换：AppLayout `<select class="lang-select">` 绑定 `locale`，`@change` 调 `setLanguage()`，选项固定 zh-CN / en-US / zh-TW 三档。AppLayout 仅包裹已登录页面（个人中心）。

### 5.5 应用挂载（src/main.ts）

- `import { i18n } from './lang'` → `app.use(i18n)`，与 Pinia / Router 并列注册。

### 5.6 已修复 bug（refreshCaptcha 抹错）

- 原实现 `refreshCaptcha()` 内会清空 `errorMsg`，导致登录失败时「先展示错误 → 自动刷新验证码 → 错误被清空」的问题；已移除该清空逻辑，`refreshCaptcha()` 现在只更新验证码状态（`captchaEnabled` / `captchaImg` / `form.uuid`）与清空 `form.code`，不再触碰 `errorMsg`。

## 8. 已知缺口（Known Gaps）

- 无测试框架、无 lint（沿用工程现状）。
- 语言切换入口仅在 AppLayout 顶栏（已登录页面）；登录页/注册页等访客页无切换入口（访客页仍按当前 locale 渲染）。
- `document.documentElement.lang` 未随语言切换同步更新（可访问性增强项）。
- 语料文件由父工程 sync 脚本生成，本工程不单独维护；语料变更需在父工程执行 sync 后重新分发。
