# 005-theme 测试用例

> 模块：005-theme（主题皮肤切换）
> 对应规格：[spec.md](./spec.md)
> 生成日期：2026-08-18

## 测试范围

本测试用例覆盖主题皮肤切换模块的核心能力：登录页圆形 emoji 按钮两态切换、个人中心「切换主题」三态选择、两入口状态同步、localStorage 持久化与非法值回退、`system` 态系统跟随与实时联动、首屏防闪烁、双皮肤视觉与品牌色一致性、既有页面兼容与可访问性。

---

## 一、登录页切换按钮测试用例

### TC-005-001：亮色下点击切换为暗色

- **前置条件**：localStorage 无 `theme` 键或为 `light`；系统不影响（显式选择优先）
- **操作步骤**：
  1. 打开登录页（当前为亮色，按钮显示 🌙）
  2. 点击右上角圆形按钮
- **预期结果**：
  - 页面即时切换为暗色（背景 `#1A1C1E`、卡片 `#26282B`）
  - 按钮图标由 🌙 变为 ☀️
  - `<html>` 的 `data-theme` 变为 `dark`
  - localStorage `theme` 写入 `dark`

### TC-005-002：暗色下点击切换为亮色

- **前置条件**：当前为暗色（按钮显示 ☀️）
- **操作步骤**：点击右上角圆形按钮
- **预期结果**：
  - 页面即时恢复亮色（背景 `#F7F5F0`、卡片 `#FFFFFF`）
  - 按钮图标由 ☀️ 变回 🌙
  - `data-theme` 变为 `light`，localStorage `theme=light`

### TC-005-003：切换无整页刷新

- **前置条件**：位于登录页，已填写部分手机号
- **操作步骤**：点击右上角圆形按钮
- **预期结果**：
  - 主题切换过程中页面不刷新、不重新加载（无白屏）
  - 已填写的表单内容与验证码图片保持原状
  - 登录主流程不受影响，仍可正常提交登录

### TC-005-004：按钮位置、点击区域与布局

- **前置条件**：分别在桌面（≥960px）与移动端（375px）视口打开登录页
- **操作步骤**：
  1. 观察按钮位置与登录卡片的关系
  2. 测量/核对按钮尺寸
- **预期结果**：
  - 按钮固定于页面右上角（绝对定位，距边缘 16px）
  - 按钮点击区域 ≥ 44×44px
  - 不遮挡手机号/密码/验证码输入框与登录按钮，两种视口下均不覆盖表单控件

## 二、个人中心「切换主题」测试用例

### TC-005-005：选择「深色」

- **前置条件**：用户已登录，进入个人中心，「偏好设置」区可见
- **操作步骤**：在「切换主题」下拉选择「深色」
- **预期结果**：
  - 界面即时切换暗色（顶栏、卡片、背景均联动）
  - 下拉保持选中「深色」
  - localStorage `theme=dark`

### TC-005-006：选择「浅色」

- **前置条件**：当前为暗色
- **操作步骤**：在「切换主题」下拉选择「浅色」
- **预期结果**：界面即时恢复亮色，下拉选中「浅色」，localStorage `theme=light`

### TC-005-007：选择「跟随系统」

- **前置条件**：当前为显式浅色或深色；操作系统为深色模式
- **操作步骤**：在「切换主题」下拉选择「跟随系统」
- **预期结果**：
  - 界面即时切换为暗色（系统当前为深色）
  - localStorage `theme=system`
  - 此后切换系统深浅色，应用实时联动（见 TC-005-010）

### TC-005-008：「切换语言」与「切换主题」相邻且独立

- **前置条件**：已登录，进入个人中心「偏好设置」区
- **操作步骤**：
  1. 确认「切换主题」位于「切换语言」之下
  2. 切换语言为 English
  3. 再切换主题为深色
- **预期结果**：
  - 两行入口上下相邻，「切换主题」在「切换语言」之下
  - 语言切换后「切换主题」行文案随语言变化（如 "Switch theme" / "Light" / "Dark" / "System"）
  - 主题切换不影响语言选择，语言选择不影响主题

## 三、两入口状态同步测试用例

### TC-005-009：登录页切换后个人中心同步

- **前置条件**：未登录，登录页为亮色
- **操作步骤**：
  1. 登录页点击右上角按钮切为暗色
  2. 输入正确凭证完成登录
  3. 进入个人中心
- **预期结果**：
  - 界面保持暗色
  - 「切换主题」下拉显示选中「深色」

### TC-005-010：个人中心切换后登录页按钮同步

- **前置条件**：已登录，个人中心将主题切为「浅色」
- **操作步骤**：退出登录回到登录页
- **预期结果**：登录页为亮色，右上角按钮显示 🌙

## 四、三态与系统跟随测试用例

### TC-005-011：默认跟随系统

- **前置条件**：清空 localStorage（无 `theme` 键）
- **操作步骤**：
  1. 将操作系统设为深色模式，打开应用
  2. 将操作系统设为浅色模式，重新打开应用
- **预期结果**：
  - 深色系统下首屏为暗色；浅色系统下首屏为亮色
  - 个人中心「切换主题」下拉显示「跟随系统」

### TC-005-012：system 态系统变化实时联动

- **前置条件**：主题为「跟随系统」，应用已打开
- **操作步骤**：不刷新页面，直接切换操作系统深浅色（如 Windows 设置 → 颜色 → 深色/浅色）
- **预期结果**：应用界面实时切换为对应皮肤，无需刷新；登录页按钮图标同步变化（若可见）

### TC-005-013：显式选择覆盖系统

- **前置条件**：操作系统为深色模式；用户在登录页显式切为亮色（`theme=light`）
- **操作步骤**：保持应用打开，切换操作系统为浅色再切回深色
- **预期结果**：应用保持亮色不变（显式选择不受系统变化打扰）

## 五、持久化测试用例

### TC-005-014：切换主题后刷新保持

- **前置条件**：已切换为暗色
- **操作步骤**：刷新浏览器页面（F5）
- **预期结果**：
  - 页面刷新后仍为暗色
  - localStorage `theme` 键值仍为 `dark`

### TC-005-015：重新打开浏览器保持

- **前置条件**：已切换为暗色
- **操作步骤**：完全关闭浏览器后重新打开应用
- **预期结果**：仍为暗色（localStorage 跨会话保留）

### TC-005-016：localStorage 非法值回退

- **前置条件**：手动将 localStorage `theme` 设为非法值（如 `blue`）
- **操作步骤**：刷新页面
- **预期结果**：
  - 不采用非法值，回退 `system`（按系统深浅色渲染）
  - 页面正常渲染，无白屏、无脚本异常
  - 个人中心「切换主题」下拉显示「跟随系统」

## 六、首屏防闪烁测试用例

### TC-005-017：暗色用户刷新无亮色闪烁

- **前置条件**：`theme=dark`（显式暗色）
- **操作步骤**：刷新页面，观察首屏
- **预期结果**：首屏直接呈现暗色背景，无「先亮后暗」闪烁（内联脚本在 body 渲染前已设 `data-theme=dark`）

### TC-005-018：system 态 + 深色系统首屏无闪烁

- **前置条件**：`theme=system`（或无该键）；操作系统为深色模式
- **操作步骤**：刷新页面，观察首屏
- **预期结果**：首屏直接呈现暗色，无亮色闪烁

## 七、变量与视觉测试用例

### TC-005-019：品牌主色一致性

- **前置条件**：分别处于亮色与暗色皮肤
- **操作步骤**：检查主按钮、标题、导航选中态等主色元素（DevTools 计算样式）
- **预期结果**：
  - 亮色下 `--color-primary` 计算值为 `#3B5998`（靛青）
  - 暗色下为 `#5B7DB1`（提亮靛青）
  - 金曦强调色（`.btn-accent`）两套皮肤均为 `#E8923C`
  - 全工程无微信绿 `#07C160` 作为主色使用（仅微信登录按钮用 `--color-wechat`）

### TC-005-020：既有页面亮色零回归

- **前置条件**：default（亮色）皮肤
- **操作步骤**：依次浏览登录页、注册页、个人中心、个人中心
- **预期结果**：
  - 各界面颜色与主题改造前一致（10 个 DESIGN.md 色彩名别名经 `var()` 解析到相同 default 值）
  - 字体、间距、圆角、阴影、动画无变化

### TC-005-021：暗色视觉走查

- **前置条件**：暗色皮肤
- **操作步骤**：依次浏览登录页（含输入焦点态、微信登录按钮 hover）、个人中心（骨架屏/错误重试/空状态/数据四态）、个人中心（弹窗、表单）
- **预期结果**：
  - 背景 `#1A1C1E`、卡片 `#26282B`、正文 `#E8E4DE`，正文对比度充足、护眼不刺眼
  - 靛青/金曦品牌元素在深底上清晰可辨（反色但保留品牌识别度）
  - 输入框焦点圈、按钮 hover、Toast、骨架屏等状态色在暗色下表现正常

## 八、可访问性与国际化测试用例

### TC-005-022：键盘可达与可访问名称

- **前置条件**：登录页
- **操作步骤**：
  1. 按 Tab 键聚焦右上角主题按钮
  2. 按 Enter / Space 触发
  3. 用读屏器或 DevTools 检查可访问名称
- **预期结果**：
  - 按钮可经键盘聚焦，`:focus-visible` 焦点圈可见
  - 键盘可触发切换
  - 可访问名称为「切换主题」（en-US 下 "Switch theme"），emoji 本身不暴露给读屏（`aria-hidden`）

### TC-005-023：个人中心下拉 label 关联与三语言文案

- **前置条件**：已登录，进入个人中心
- **操作步骤**：
  1. 点击「切换主题」行文案（label）
  2. 依次切换界面语言为 简体中文 / English / 繁體中文
- **预期结果**：
  - 点击 label 可聚焦对应下拉（`for` 关联正确）
  - 三语言下「偏好设置 / 切换语言 / 切换主题 / 浅色 / 深色 / 跟随系统」文案正确切换（如 English 下 "Preferences" / "Language" / "Switch theme" / "Light" / "Dark" / "System"；繁體下「偏好設定 / 切換語言 / 切換主題 / 淺色 / 深色 / 跟隨系統」），无缺失 key 回退原样显示
